================================================================================
                          ARCHITECTURE HIGHLIGHTS
================================================================================

1. Separation of Concerns
   - bot.py: Command routing
   - handlers/: Business logic (pure functions)
   - services/: External APIs (LMS, LLM)
   - config.py: Environment management

2. No Secrets in Code
   - BotSettings loads from .env.bot.secret
   - All URLs and keys from environment
   - pydantic-settings validates types

3. Async I/O
   - httpx for HTTP (replaces requests)
   - All service methods async/await ready
   - Supports concurrent operations

4. LLM Tool Calling (Task-3 specific)
   - Formal ToolDefinition dataclass
   - Each tool: name, description, input_schema
   - LLM chooses based on descriptions
   - NO regex, NO keyword matching
   - If LLM picks wrong tool → improve description

5. Docker Networking (Task-4 specific)
   - Services on lms-network bridge
   - Use service names: backend:42002 (not localhost)
   - Environment variables for all config
   - Multi-service orchestration ready

================================================================================
                         DESIGN DECISIONS MADE
================================================================================

✅ Why handlers are pure functions?
   - Testable without Telegram API
   - Reusable from CLI, tests, or bot framework
   - Easy to understand and modify

✅ Why async httpx instead of sync requests?
   - Prepares for concurrent API calls
   - Better performance for I/O
   - Modern Python standards

✅ Why formal tool descriptions for LLM?
   - LLM quality depends on description quality
   - No code-based routing means true LLM routing
   - If wrong tool → improve description, not code
   - Matches production LLM APIs (OpenAI, Anthropic)

✅ Why service names in docker-compose?
   - Services find each other on network
   - localhost inside container is container's own loopback
   - Scales: add service, update DNS (automatic)

✅ Why pydantic-settings?
   - Type validation for all config
   - Required fields enforced
   - Better than os.getenv()
   - Standardized across Python projects

✅ Why uv instead of pip?
   - Fast, deterministic, lock-file based
   - No dependency conflicts
   - Single tool for everything
