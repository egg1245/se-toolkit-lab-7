# Лабораторная: Подготовка окружения (полная)

Этот документ содержит пошаговую инструкцию по подготовке рабочего окружения для лабораторных заданий и проверочные команды.

Цель
- Дать студенту простой, воспроизводимый набор шагов для запуска бэкенда, фронтенда и бота локально.
- Обеспечить минимальные проверки, чтобы избежать ошибок во время выполнения заданий.

Краткие требования
- macOS (инструкции для zsh). Аналогично работает под Linux.
- Docker и docker-compose (или `docker compose`) для запуска контейнеров.
- Python 3.10+ (проект использует `pyproject.toml`).
- Git (репозиторий уже должен быть клонирован в рабочую папку).

Важное про плагиат (коротко и ясно)
- Нельзя выдавать чужие решения за свои. Открытое использование чужого кода или текста допустимо только при явной ссылке и минимальной адаптации.
- При использовании фрагмента кода/алгоритма из внешнего источника: добавьте комментарий с ссылкой и коротким объяснением, что было заимствовано и почему.
- Полный перенос решения без указания источника недопустим. Преподаватели применяют автоматические и ручные проверки на сходство — оформляйте цитаты честно.

Как цитировать — короткий пример (в коде):

# Пример: адаптация функции из внешнего ресурса
# Источник: https://example.com/some-algorithm (дата доступа 2026-03-21)
# Кратко: изменена обработка ошибок и имплементация логики X

def adapted_function(...):
    ...


Проверки окружения (быстрая диагностика)

1) Проверить, что бэкенд (если вы запускаете локально) доступен по документации OpenAPI:

```bash
# macOS/zsh
curl -sf http://localhost:42002/docs || echo "backend not available at http://localhost:42002/docs"
```

2) Проверить, что файлы с секретами существуют (они gitignored):

```bash
# Перейдите в корень проекта
ls -la .env.bot.secret .env.docker.secret 2>/dev/null || echo "Проверьте .env файловые секреты (отсутствуют)"
```

3) Запустить контейнеры через docker-compose (если проект рассчитан на это):

```bash
# В корне репозитория
docker compose up -d --build
# Подождите, затем проверите логи:
docker compose logs --tail=50
```

4) Запустить тесты Python (при наличии):

```bash
# Используйте ваш виртуальный окружение/инструмент, например:
python -m pytest -q
# или, если вы используете poetry:
# poetry run pytest -q
```

Если тесты падают, сначала посмотрите вывод, затем запустите только проблемный модуль, чтобы сократить шум.

Как запускать бот в тестовом режиме (общее указание)
- Проект содержит `bot/` — в нём есть точка входа. Есть режим тестирования, который позволяет вызывать обработчики без Telegram.
- Найдите `bot/pyproject.toml` или `bot/bot.py` для конкретных подсказок по запуску в вашей копии репозитория.

Рекомендации по отладке и следующая проверка
- Если какой-то сервис недоступен, проверьте докер-логи, затем сетевые настройки (порт/файервол).
- Если упираетесь в ошибку аутентификации API — убедитесь, что вы используете правильный ключ (переменные окружения).

Контактные инструкции (для преподавателя/ассистента)
- При сбоях приложите вывод `docker compose logs`, `pytest -q` и `curl` проверки, а также краткое описание шага, на котором произошёл сбой.
